# Lessons Learned: InSIS Extractor

1. **Jules Desync Mitigation**: When spinning sub-agents like Jules on active branches, their working directory is snapshotted. If foundational or structural changes occur locally (e.g. auth-guards or DOM dumps being created), the sub-agent will lack this context unless explicitly committed and pulled. It is often faster and safer to implement precise, deterministic scrape routines locally if the DOM bounds are already known.
2. **Playwright `goBack()` Traps**: Traditional browser history navigation via `page.goBack()` within intricate authenticated environments like InSIS can trigger timeouts because the application pushes silent states or modifies `History`. Direct navigation to absolute static endpoints (e.g., `terminy_seznam.pl` and `rozvrhy_view.pl`) is safer and much faster than simulating UI back-buttons.
3. **Data Extraction Paradigms**: Separating the DOM fetching logic from the structural parsing logic is highly effective. Using Playwright solely for network transit/auth validation and relying on lightweight parsers (like `jsdom` or `cheerio`) against the raw HTML dumps ensures stability. Changes in extraction needs do not require re-triggering network bottlenecks.
4. **Table Heuristics**: Academic portals like InSIS rely heavily on densely nested generic `table` layers without semantic IDs. Parsing strategies must rely on table iteration (`tr.uis-hl-table`), structural depth limits, and reliable column indices to accurately scrape values like Term Dropboxes and Exam Capacities.
5. **String Sanitization in Bash scripts**: When automating course folder creation and linking based on JSON data (like INSIS profiles), it is crucial to sanitize the extracted strings. Course names might not have standard IDs (e.g., "IS/ICT Project Management") which can result in unintended nested directories if slashes are not treated properly (e.g., replacing '/' with '-').
6. **Symlinks and Read-only intent**: Symbolic links in Linux cannot intrinsically restrict write access to their targets. To denote a link as "readonly" without modifying the source permissions (which could break automated downloaders), a clear naming convention (like `Dokumentový_server_READONLY`) is the safest approach, relying on user discipline.
