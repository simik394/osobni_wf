
### Moodle Document Crawling
- **CDP Automation in Moodle**: By connecting to an existing browser via CDP (`127.0.0.1:9222`), we bypassed complex authentication methods.
- **Handling Moodle Tree Structure**: Instead of clicking through paginated layouts manually, the Moodle Boost theme conveniently lists all sections and activities (`mod/resource`, `mod/folder`, etc.) implicitly in the left navigation sidebar under `courseindex-section`. Parsing this DOM `ul` element reveals 100% of all learning materials globally.
- **Zip Folder Handling**: Moodle folders (`mod/folder`) often contain multiple files. Rather than iterating DOM nodes within the folder, submitting the "Stáhnout složku" (download folder) form using its query params dynamically fetches a ZIP archive, which the script extracts natively in Node using `unzip`. This proves much more reliable and preserves absolute structure.
- **Diacritics the hard way**: Do not use `decodeURIComponent(escape())` on UTF-8 strings (especially Czech diacritics like 'Ř'). It will raise `URIError: URI malformed`. A reliable fix is simply stripping illegal directory characters natively via standard Regex replacement operations.
- **Browser State Context**: Moodle's dashboard and course links are dynamically generated. Relying on whatever page is initially active limits discovery. The script must explicitly navigate to the dashboard (`https://moodle.vse.cz/my/`) to reliably enumerate all enrolled target courses regardless of the user's initial active tab.
- **Handling Unknown/Complex Moodle Modules**: Moodle contains various activities like `turnitintooltwo`, `choicegroup`, `quiz`, or direct pages (`page`) which contain the actual curriculum in their HTML body, rather than attached files. Instead of skipping "unknown" types, the script must navigate to these modules and save their `innerHTML` as readable offline `.html` pages to achieve 100% extraction coverage without missing crucial data.
- **Extracting Moodle Books**: Moodle "Kniha" modules (`mod/book`) split content into multiple subchapters. Iterating through them individually via DOM click events is slow and error-prone. A robust solution is to locate the "Vytisknout celou knihu" (Print complete book) link under `tool/print/index.php` which generates a single clean HTML page encompassing every chapter of the book at once.
- **Offline UX Structure**: To make raw downloaded content readable outside of the browser, generating a simple `index.html` that mirrors the exact sequence and sections of Moodle vastly improves the usability of the downloaded corpus.
- **HTML→Markdown for LLM/NotebookLM**: Raw HTML from Moodle contains too much UI chrome (navigation, forms, buttons, badges) for LLM consumption. Converting to Markdown using `turndown` + `turndown-plugin-gfm` after stripping Moodle chrome (nav, .breadcrumb, .activity-navigation, .singlebutton, etc.) produces clean, lossless content suitable for NotebookLM upload. The `extractMainContentAsMarkdown()` method targets `[role="main"]` and removes ~15 selector categories of UI noise before conversion. Tables are preserved via the GFM plugin. Images retain their `![alt](src)` syntax with full Moodle pluginfile.php URLs. A separate `convert_html_to_md.js` batch script handles offline conversion of existing downloads.
- **NotebookLM Upload Automation**: Google frequently changes NotebookLM DOM structure and classes, breaking traditional CSS-selector automation (like the original `rsrch` `notebooklm-client.ts`). Upload scripts using Playwright must use `page.evaluate()` to dynamically parse the DOM text (`textContent` matching "Přidat zdroje" or "Copied text") and ARIA labels rather than strict `.click()` locators. Additionally, single-page apps like NotebookLM leave "ghost" popup states in the DOM. Calling `page.reload()` before every single uploaded file dramatically improves long-term upload stability by guaranteeing a pristine DOM state.
